# Vehicle Telemetry Log Analyzer
#### Video Demo: [video](https://youtu.be/ClJSXDWT2As?si=eU56yL6dJLG2LtNK)
#### Description:

Vehicle Telemetry Log Analyzer is a command-line Python program that reads vehicle telemetry log files, validates each line, analyzes the valid data, and produces a readable report. I built it around a simple telemetry format containing a timestamp, log level, and key-value fields such as temperature, supply voltage, left and right motor RPM, motor commands, throttle, and steering. The program can also process explicit `WARN` and `ERROR` event records generated by the vehicle.

The main file is `project.py`. Its `main` function handles command-line arguments with `argparse`, loads the requested log file, runs the analysis, builds a summary, and decides what output to display or export. Running the program with only a path prints the complete vehicle telemetry report. The optional `--stats`, `--events`, and `--malformed` flags can be used to display only one part of that report. The `--csv` option exports valid telemetry data to a CSV file, while `--json` exports the analysis summary in JSON form.

Parsing and validation are handled by `parse_record` and `load_log`. `parse_record` uses a regular expression to validate the basic structure of one log line, separates its key-value fields, rejects duplicate or missing fields, and converts known numeric fields to integers or floats. A line that cannot be interpreted correctly is marked as malformed with a reason. `load_log` reads the complete file, keeps successfully parsed records, and separately stores malformed line numbers and their error reasons. This allows one bad line to be reported without stopping the analysis of the rest of the file.

`analyze_records` processes the valid telemetry samples. It calculates minimum, maximum, and average values for temperature, supply voltage, left and right motor RPM, motor commands, throttle, and steering. It also derives vehicle speed from the average wheel RPM and the wheel diameter stored in the session-start record.

The program also handles faults and unusual operating conditions. `log_events` counts explicit warning and error events already present in the log and also uses `detect_anomalies` to inspect ordinary telemetry samples. The anomaly checks currently cover high temperature, low supply voltage, motor stall, and motor speed mismatch.

`format_report`, `format_stats`, `format_events`, and `format_malformed` produce the terminal output. The full report includes session information, telemetry statistics, event totals, and malformed-line diagnostics. `export_csv` writes valid telemetry records in a tabular format that can be opened in spreadsheet or data-analysis software. `export_json` writes the analysis summary in a structured json form.

`test_project.py` contains pytest tests for the major custom functions in `project.py`, allowing the parsing, analysis, and event-processing logic to be checked independently of the command-line interface. `requirements.txt` lists the pip-installable dependency needed to run the test suite. The remaining modules used by the program, including `argparse`, `re`, `csv`, `json`, and `statistics`, are part of Python's standard library.

One design choice I made was to keep malformed input separate from valid but abnormal telemetry. For example, a non-numeric temperature value is malformed, while a correctly formatted temperature that is unusually high is still valid telemetry and can be detected as an anomaly. I also kept the log analyzer independent from the hardware that creates the logs (an ESP32 car project im working on). This makes it possible to test the program using sample files now and later use the same analyzer with telemetry captured from an actual embedded system.
